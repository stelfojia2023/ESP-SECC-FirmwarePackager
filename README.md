# ESP-SECC 固件联合打包工具 V0.0.1

本工具将 PFC、LLC、M4、PLC、ESP32 中选定的 1～5 份固件打包成一个 BIN，生成时自动校验，可查看本次生成包的包头，也可按需上传到 FTP。交付的 `dist/FirmwarePackager.exe` 是 Windows 10/11 64 位图形程序，不需要安装开发环境。运行依赖 Windows 自带的 .NET Framework 4.x；打包无需联网，FTP 上传需要网络和服务器。

[单独下载 FirmwarePackager.exe](https://github.com/stelfojia2023/ESP-SECC-FirmwarePackager/raw/refs/heads/main/dist/FirmwarePackager.exe) · [下载五类测试 BIN](https://github.com/stelfojia2023/ESP-SECC-FirmwarePackager/raw/refs/heads/main/test-vectors/five-test-bins.zip)。仓库为私有仓库，需要登录有权限的 GitHub 账号。

**V1 是候选包格式。当前设备尚未接入联合包解析和多模块升级；候选的 6 MiB 暂存区和 2.5 MiB ESP32 应用槽不是当前设备配置。** 上传仅发送文件到用户指定的 FTP 目录，不烧录设备、不执行升级。

**支持选择文件夹后一键加载，以及一键清理五类固件选择。只扫描所选文件夹当前层，不递归子目录；清理不会删除磁盘文件，也不会清空 FTP 配置或输出位置。**

## 使用方法

1. 双击 `dist/FirmwarePackager.exe`。工具、输入固件和输出路径可包含中文与空格。
2. 将 BIN 文件拖入对应类型的输入框，也可以粘贴文件路径或点击文件夹图标。每类最多选择一个文件，未选择的类型不会占用固件空间。
3. 名称默认为整个文件名去掉 `.bin` 后缀，可修改；版本从下划线后的 `V`/`v` 开始，取到下一下划线或点之前，保留原大小写。例如 `PFC_ABC_V001B02.bin` → 名称 `PFC_ABC_V001B02`、版本 `V001B02`。单文件缺版本可选入，须在生成前手动补填。名称和版本长度按 UTF-8 字节数限制，超长会报错，不会截断。
4. 已选固件自动显示在下方列表，清除选择后对应行消失；输入完整通过校验后显示实际包内偏移，否则显示“待校验”。错误与大小限制提示显示在操作结果。偏移相对于联合 BIN 起点，不是目标烧录地址。
5. 选择输出 BIN 路径，点击“包生成”。已有输出需要确认替换；输出不能与任何输入固件指向同一文件。成功后结果区显示总大小及每类固件的名称、版本和大小。
6. 生成成功后，点击“查看包头”查看本次生成文件的前 4096 字节；程序不提供独立打开已有包进行校验的入口。
7. 在右侧文件/URL/用户名/密码区域操作。生成后默认填入刚生成的联合包；也可不打包，直接拖入或浏览选择任意本地文件。地址、用户名和密码启动时已有默认值，可修改；也可粘贴 `ftp://用户名:密码@服务器:端口/目录` 自动分离账号。点击“上传到 FTP”并确认目标。目录后自动追加当前所选文件的文件名。用户名或密码中的 `@`、`:` 等 URL 特殊字符需百分号编码，密码在界面中遮罩。
8. 点击“打开 FTP 目录”查看服务器返回的条目，不需要选择本地文件。若已选文件，弹窗提示是否有同名条目；同名只代表名称相同，不证明文件类型或内容一致。目录读取失败会提示原因。列表按服务器返回显示，支持 UTF-8 及 GBK 编码，最多 10,000 个条目、4 MiB；超过限制时提示无法完整显示。

联合包模式上传前重新校验 V1 格式；独立本地文件模式直接上传，不强加包格式或 6 MiB 限制。两种模式均收到 FTP 服务器最终成功应答后才显示成功；失败时显示原因。普通 FTP 以明文传输账号、密码和文件，服务器上同名文件可能被覆盖。成功表示服务器确认传输完成，不包含远端文件回读校验，也不代表设备已升级。

启动默认密码内置在程序和源码中，持有者可读取；在窗口中修改的账号和密码不会保存，下次启动恢复默认值。

按用户确认的工具策略：PFC/LLC 各最多 250 KiB（256,000 字节）、M4 512 KiB（524,288 字节）、PLC 2 MiB（2,097,152 字节）、ESP32 2.5 MiB（2,621,440 字节）；空文件或超限文件在单选、拖拽、批量加载及打包时拒绝。总包仍最多 6 MiB（6,291,456 字节），包含包头和对齐填充。上述为工具接收限制，不是对实际设备分区容量的保证。数据读取期间输入文件发生变化、输出不可写、与输入相同或生成中途失败时不会报告成功；生成先写同目录临时文件、校验后再发布到目标路径。

底层整包 MD5 按包头 MD5 字段置零规则计算，**不同于直接对最终 BIN 执行普通 `md5sum`**。MD5 只检查数据一致性，不验证发布者身份。

## 在 Windows 上构建

准备 Windows 10/11 64 位和系统的 .NET Framework 4.x；构建使用系统 `Framework64/v4.0.30319/csc.exe`，不需下载包。将本工程复制到 Windows 磁盘，在工程目录打开 PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

输出为 `dist\FirmwarePackager.exe`。该脚本仅使用 Windows 和 .NET Framework 自带程序集，没有第三方构建依赖。

## 复跑测试

先按上文构建，然后在 Windows 已解锁的交互桌面执行；GUI 测试会短暂打开窗口并操作文件对话框。硬链接保护测试要求临时目录所在卷支持硬链接（如 NTFS）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run-tests.ps1
```

脚本打印临时证据目录，其中 `core results` 保存 31 组、预算上限测试包及输入。用 Python 3.10 或更高版本（仅独立核验脚本需要，工具本身不需要）核验该目录：

```powershell
python .\tests\independent_verify.py "<打印的证据目录>\core results"
python .\tests\verify_vector.py .\test-vectors
```

测试会创建自己的新临时目录，不覆盖已有测试证据。请不要把测试数据误当成正式固件。


## 文件夹识别

仅识别以 PFC、LLC、M4、PLC、ESP32 开头的 `.bin` 文件，类型和扩展名大小写不敏感。每类只有一个匹配文件、版本可解析且校验通过才更新该栏。同类多个匹配文件、缺版本、空文件、超限或无效元数据均跳过并记录原因，保留原选择；无匹配项也保留。不会自动猜测最新版本或挑选最大文件。手动选择可修改名称/版本；识别到与所选栏不同的类型时拒绝。

## 操作说明与包头查看

内容区右上角 ⓘ 打开简明操作说明。成功生成联合包后，输出区域的“查看包头”可读取本次生成文件前 4096 字节：每行 16 字节，按 8+8 分组，右侧 ASCII 将不可打印字节显示为点。支持十六进制地址 0x0000～0x0FFF 跳转与高亮。只读且不读取后续固件；文件缺失、不足4096字节或包头与生成时不同会报错。它不是整包内容查看器。

五类型硬上限同样作用于生成及联合包 FTP 上传的内部校验：历史超过 PFC/LLC/M4/PLC 上限的包，尽管此前可生成，新版也会拒绝。普通文件 FTP 入口不套用固件限制。
