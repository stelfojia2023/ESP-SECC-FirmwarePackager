# 开发与验证

## 构建

在 Windows 10/11 64 位环境准备系统自带的 .NET Framework 4.x。工程使用 `Framework64/v4.0.30319/csc.exe`，无需下载第三方构建依赖。在工程根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

输出为 `dist\FirmwarePackager.exe`。程序图标和声音资源在构建时嵌入，单独运行 EXE 不需要携带资源文件。

## 测试

先构建，再在 Windows 已解锁的交互桌面运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run-tests.ps1
```

测试会创建新的临时目录、打开窗口并操作鼠标；硬链接保护测试需要支持硬链接的卷。FTP 测试使用本机模拟服务和合成账号，不连接实际 FTP 服务器或设备。

脚本输出的证据目录中包含 `core results`。使用 Python 3.10 或更新版本独立核验：

```powershell
python .\tests\independent_verify.py "<输出的证据目录>\core results"
python .\tests\verify_vector.py .\test-vectors
```

`test-vectors` 是合成测试数据，不可用于设备升级。

## 当前验证与发布

[V0.0.4 七色验证](V0.0.4七色验证.md)记录了本机环境、结果和未验证范围；对应日志和校验清单在 `evidence/seven-colors-0.0.4/`。`.github/workflows/windows-build.yml` 负责 Windows 构建及自动检查；是否发布 Release 按以下版本约定执行。

模拟字体尺寸或控件绘制不等于实际切换系统 DPI；测试通过也不代表已验证真实 FTP、运营平台或设备升级。

## 版本与发布约定

本约定仅用于本工程：**提交一个新的工程版本时必须升级版本号，并在 PR 说明中写明旧版本 → 新版本及主要变化。** 不是每个普通提交、测试修正或同一 PR 内的小步修改都要增号。

- 工具版本与联合包格式版本独立；版本变更应写明各自是否变化。
- 一个版本内的准备、验证和修正提交可共用该目标版本。
- 窗口版本、AssemblyVersion、AssemblyFileVersion、app.manifest、构建产物名与现行测试断言保持一致。
- README 说明当前版本及可取得的产物；验证记录只对实测版本负责，更新时不能把旧结果改写为新版本结果。
- 工程升级版本不等于授权发布 GitHub Release；只有明确要求发布时才更新发布元数据和校验摘要。
- `.github/release.json` 记录最近一次发布的版本与 EXE 摘要，不是工程版本权威来源。发布时应与目标版本及待发布 EXE 一致。
- 发布前核对实际构建源提交、测试结果、EXE 版本及摘要。不把旧 dist 或历史 Release 资产误称为当前新版本。
