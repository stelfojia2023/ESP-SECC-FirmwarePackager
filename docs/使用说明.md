# 固件联合打包工具使用说明

双击 `FirmwarePackager.exe` 启动。支持 Windows 10/11 64 位，依赖系统的 .NET Framework 4.x；无需安装开发工具。打包和校验无需联网，FTP 上传需要连接服务器。

**当前 V1 包格式供评审使用，现有设备尚未接入联合包解析，不能直接用于现有设备升级。** 界面中的 6 MiB 暂存区与 2.5 MiB ESP32 应用槽均为候选方案。

1. 将 BIN 拖入对应类型的输入框，或粘贴文件路径，也可以点击文件夹图标。可选择 1～5 类，每类一个文件，未选类型不会被写入包。
2. 检查并按需修改默认固件名称和版本；文件名中含下划线后的 V 版本时会自动识别，缺少版本时须手动填写，例如 `V000B01D15`。
3. 检查预览中的类型、名称、版本、文件大小和包内偏移，以及总大小与警告。包内偏移从联合 BIN 开头计算，不是目标芯片的烧录地址。
4. 选择输出 BIN 路径并点击“包生成”。成功后结果区显示路径、总大小及各固件信息。
5. 生成成功后点击“查看包头”，可只读查看本次生成文件的前 4096 字节并定位地址。界面不提供独立打开已有包进行校验的入口。
6. FTP 地址、用户名和密码启动时已有默认值，可按需修改；也可粘贴 `ftp://用户名:密码@服务器:端口/目录`，工具会自动分离账号和密码。密码在界面上遮罩，修改值仅在当前窗口保留，重新启动恢复默认值。默认密码内置在程序和源码中，持有者可读取。账号或密码中的 `@`、`:` 等 URL 特殊字符需先百分号编码。
7. 点击“上传到 FTP”，核对目标地址并确认。生成的联合包在上传前重新校验；也可选择普通本地文件直接上传。收到服务器最终成功应答才显示成功，失败时显示原因。服务器上同名文件可能被覆盖；普通 FTP 会明文传输账号、密码和文件。成功不包含远端回读校验，也不代表设备升级成功。
8. 点击“打开 FTP 目录”查看当前地址的目录条目，无需选择本地文件。已选文件时，弹窗会提示是否存在同名条目；这仅比较名称，不验证条目类型或内容。读取失败时显示原因；目录超过 10,000 个条目或 4 MiB 时会提示不能完整显示。
9. 点击顶部“设备升级”切换页面。新生成的联合包自动关联，也可拖入或选择其他 BIN；可填写本地设备 IP、端口，或切换远程填写运营平台地址和 CPID。页面仅预留配置，本地协议和平台接口尚未接入，不能实际升级。窗口中填写的升级配置不会保存。

PFC 和 LLC 原始固件各不得超过 250 KiB，M4 不得超过 512 KiB，PLC 不得超过 2 MiB，ESP32 不得超过 2.5 MiB；联合包包括包头与填充不得超过 6 MiB。文件为空、超限、不可读取、未填版本、文本超过 UTF-8 字节限制等情况会报错。

整包 MD5 的计算会将包头中的整包 MD5 字段视为全零，因此不同于直接对最终 BIN 执行普通 `md5sum`。MD5 只检查数据一致性，不能验证发布者身份。

`V1格式说明.md` 描述待评审格式的字节布局；`test-vectors` 是合成测试样包，不能用于升级。完整源码、构建和回归说明位于独立工程目录。
