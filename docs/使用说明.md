# 使用说明

双击 `FirmwarePackager.exe` 启动。程序支持 Windows 10/11 64 位，依赖系统的 .NET Framework 4.x；打包无需联网，FTP 操作需要连接服务器。固件及输出路径可包含中文和空格。

## 选择固件

在“固件打包”页拖入、粘贴路径或选择 BIN，可选 PFC、LLC、M4、PLC、ESP32 中的 1～5 类，每类一个。名称默认取文件名去掉扩展名；版本从下划线后的 `V` 或 `v` 开始，取到下一个下划线或点之前，例如 `PFC_ABC_V001B02.bin` 识别为 `V001B02`。未识别到版本时，可手动补填。名称和版本各最多 39 个 UTF-8 字节，超长不截断。

“一键加载”只扫描所选文件夹当前层。每类仅有一个有效匹配文件且版本可识别时才自动更新；同类重复、缺版本、空文件、超限或无效项会跳过并保留原选择。“一键清理”不删除磁盘文件，也不清空 FTP 配置、输出位置或操作记录。

| 固件类型 | 原始文件预算或上限 |
| --- | ---: |
| PFC、LLC | 各 250 KiB 预算 |
| M4 | 512 KiB 预算 |
| PLC | 2 MiB 预算 |
| ESP32 | 2.5 MiB 上限 |

空文件、ESP32 超限文件和超过 6 MiB 的联合包会被拒绝；联合包上限包含包头和对齐填充。PFC、LLC、M4 或 PLC 超预算时显示告警，仍可在整包允许范围内生成。这些工具限制不代表设备已具备相应分区。

## 生成和查看

选择输出 BIN 的保存位置并点击“包生成”。输出不能与输入固件指向同一文件；已有输出会要求确认替换。程序先写入同目录临时文件，经校验后发布到目标路径；失败不会报告成功。成功后，结果区显示路径、总大小及固件信息。列表中的偏移相对于联合 BIN 起点，不是芯片烧录地址。

点击“查看包头”可只读查看本次生成包的前 4096 字节，并定位 `0x0000～0x0FFF` 的地址。文件缺失、长度不足或包头与生成时不同会报错；该入口不能独立打开已有包。

新包使用 `0x28` 目录布局，不能与旧工具的 `0x80` 布局混用；旧包需要重新生成。

## FTP

地址、用户名和密码启动时为空。可分别填写，也可粘贴 `ftp://用户名:密码@服务器:端口/目录` 自动分离账号；账号或密码中的 `@`、`:` 等 URL 特殊字符需先百分号编码。密码在界面遮罩，填写值不会保存到下次启动。

生成后默认选中刚生成的联合包；也可选择普通本地文件。“上传到 FTP”需确认目标，工具会在目录后追加所选文件名：联合包上传前会再次校验，普通文件不套用包格式及 6 MiB 限制。只有收到服务器最终成功应答才显示成功；这不包含远端回读校验，也不代表设备已升级。普通 FTP 明文传输账号、密码和文件，服务器上的同名文件可能被覆盖。

“打开 FTP 目录”无需选择本地文件。已选择文件时，仅按区分大小写的名称比较是否存在同名条目，不验证远端类型或内容；目录读取支持 UTF-8 及 GBK，超过 10,000 个条目或 4 MiB 时提示无法完整显示。

## 设备升级

新生成的联合包自动关联到“设备升级”页，也可选择其他本地 BIN。页面提供本地设备 IP／端口和远程运营平台地址／CPID 等配置，但本地协议和平台接口尚未接入，“开始升级”不可用。当前 V1 是待评审格式，不能据此将生成包用于现有设备升级。

## 界面与记录

顶部右侧七个色圈可直接切换配色，悬停显示颜色名称；首次使用为银色，之后恢复上次选择。操作结果按本机时间追加，切换页面、清理输入或配色不会清除；关闭程序后不保存记录。

格式与校验规则见 [V1 格式说明](V1格式说明.md)。`test-vectors` 中的文件是合成测试数据，不能用于设备升级。
