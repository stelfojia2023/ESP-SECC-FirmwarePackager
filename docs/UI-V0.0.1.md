# V0.0.1 界面与交互

> 本文记录此前的界面设计和历史验证；当前版本已移除独立“包校验”入口，“查看包头”位于“包生成”旁边。当前使用方式以 README 为准。

## 历史设计原则（现行外观已调整）

- 实用优先。功能不减，只移除大幅品牌横幅、重复标题和说明。
- 当前采用银白浅灰、柔和微光泽与轻浮卡片；原暖灰白配色已被替换。组内紧凑、组间宽松继续保留。实际色值和绘制规则以[当前视觉规范](视觉规范.md)为准。
- 按钮比例适中，有轻微起伏、悬停和按压反馈；避免细长按钮。
- 左侧五个独立固件卡，文件夹选择与叉号清除；名称和版本使用不入真实值的占位。右侧三个卡片：文件夹加载/一键清理、包校验/包生成、FTP。五个主按钮统一尺寸。文件列表随选择自动增减，实际偏移只在校验成功后显示。底部操作结果至少十行高度，错误红色，长内容内部滚动。
- 点击使用轻巧 B 音色，成功、失败分别提示。音效默认启用，不设置选择开关；结果始终可见；FTP 状态统一显示在底部操作结果中。
- 音效为本项目原创合成资源，内嵌 EXE，不依赖旁置 WAV。

## 功能边界

保留五类输入、拖放与粘贴、名称/版本编辑、清除、大小/预算/偏移预览、生成、打开校验和 FTP 上传。

包格式仍为 V1；本轮按用户确认，将每类型大小预算升级为加载和打包硬限制，数值见 README。FTP 新增独立普通文件入口：生成成功后默认最近生成的联合包，并在上传前保持 V1 校验；未生成时文件框为空、提示拖拽或浏览，也可选择任意本地文件直接上传，不强加包格式和 6 MiB 限制。FTP 直接在主界面操作；上传中冻结来源和目标，完成后恢复，关闭程序时保留中断风险确认。普通文件采用流式传输，选择模式和确认框明确标示是否校验联合包。工具版本 V0.0.1 独立于包格式；V1.0.0 留作后续正式发布。设备端尚未接入联合包解析；6 MiB/2.5 MiB 候选设备配置不因 UI 更新成为已部署能力。移除打包格式说明及 FTP 常驻说明；设备支持边界保存在本文与README，保留上传前明文传输、同名覆盖风险确认。

## 构建与验证

- `build.ps1`：Windows 原生 .NET Framework 编译，三个声音资源内嵌，产出 `dist/FirmwarePackager.exe`。
- `.github/workflows/windows-build.yml`：只读权限，官方 checkout/upload-artifact 固定版本；构建、核心、FTP、UI 控件契约及独立 Python 校验，不部署。
- `tests/UiContractTests.cs`：验证版本、功能控件、声音资源、动态列表、默认音效开启与无音效开关，以及绘制，不替代真实鼠标/键盘/拖放测试。
- `tests/run-tests.ps1`：仍需解锁的真实 Windows 桌面，运行原有完整交互回归。

本次本地环境为 Linux：Mono 交叉编译成功，参考向量独立验证通过，FTP 原30项及新增独立文件场景共62断言通过；核心测试通过组合/预算/损坏阶段后在 Windows 硬链接 API 停止，因此不标记完整核心通过。Linux Mono 控件契约与临时显示会话的布局截图已检查；此结果不等于真实 Windows GUI、DPI、原生拖放或音频体验通过，这些仍待实机确认。Windows CI 结果以对应提交的运行记录为准，不沿用旧版 evidence。

## 文件夹加载更新

本轮紧凑布局维持五卡、右侧三块、动态列表和底部十行结果。文件夹仅扫描当前层；唯一有效项更新，重复、缺版本及错误项保留原选择并给出结果。名称/版本规则及字节上限见 README。一键清理只清固件选择，保留磁盘文件、FTP 配置和输出位置。手动浏览、拖拽和 Ctrl+V 粘贴统一校验后更新，失败不覆盖旧选择。

操作说明放内容区右上角小ⓘ，不加卡片；查看包头放结果标题右侧，仅成功生成后启用。只读4096字节、8+8十六进制与ASCII、范围内地址跳转高亮，不读取后续固件。与本次生成头快照不符时拒绝；这不是整包再次校验。
