# ESP-SECC 固件联合打包工具：功能规格

> 状态：用户确认的产品规格；未实现或待确认的项目单独标注。
> 基线：V0.0.4 的行为核查基于 `35294f2ac859e021eb88b3f69be6ecb3e93a2d48`；V0.0.6 按本次要求更新包布局、字段长度和预算规则。
> 范围：独立 Windows 工具；不改变 ESP-SECC 设备端固件。

本稿分开标记 **当前实现**、**用户已确认的目标** 和 **待确认**。当前实现表示对基线代码和文档的核查，不自动表示设备联调通过；用户确认的目标若尚未实现，会单独列出差异。本文不记录实际连接凭据。

## Problem Statement｜问题陈述

固件操作人员需要将不同模块的 BIN 组合成联合包，查看包信息并上传到 FTP；后续还希望从同一工具进入本地或远程设备升级。现有功能可以操作，但文件限制、自动识别、包内地址、上传结果和日志等规则散落在代码、使用说明与格式文档中。部分说明互相冲突，难以判断哪些行为已经实现、哪些只是候选设计，以及怎样验收。

## Solution｜解决方案

形成一份以实际用户操作为主线的功能规格，统一描述输入、加载、打包、包头查看、FTP、记录、界面及升级页；包格式的逐字节布局由 V1 格式说明负责。规格保留与当前版本不一致的已确认目标和未决事项，不将设备端未确认的协议、地址或升级成功条件写成事实。

## Implementation Decisions｜功能与设计规则

以下编号为本评审稿的追溯编号；并不表示已批准编码。未列为目标的现状仍需评审。

### 1. 运行、界面与配色

- **UI-01｜当前实现：**Windows 10/11 64 位图形程序，单个 EXE 交付；依赖系统 .NET Framework 4.x。打包不需网络，FTP 需连接服务器。
- **UI-02｜用户已确认：**顶部提供“固件打包”“设备升级”和“! 操作说明”；功能分组清楚，布局紧凑，避免大面积无用留白，文字、按钮及提示不应被裁切。
- **UI-03｜用户已确认、当前实现：**顶部七色圈顺序为银、蓝、紫、粉、橙、黄、绿。首次或配置无效时为银色；切换立即生效并保存上次选择，窗口内输入和结果不丢失。无法保存时提示下次可能无法恢复。
- **UI-04｜当前实现及用户要求：**中文常用字体为 Microsoft YaHei UI，普通文字 9.5 pt；包头等宽数据使用 Consolas。字体与七套具体色值由专门规范维护；不修改现有机器人图标，换肤也不改变功能或字号。
- **UI-05｜当前实现和限制：**程序声明系统 DPI 感知；实际 Windows 125%／150% 缩放、多屏和最终视觉效果需按验证记录分别确认，不将模拟绘制当成系统设置实测。

### 2. 固件输入与自动加载

- **IN-01｜当前实现：**支持 PFC、LLC、M4、PLC、ESP32 五类，每类一个文件；PFC、LLC、M4、ESP32 仅支持 `.bin`，PLC 不限文件后缀。通过拖拽单个文件、复制单个文件或粘贴路径、文件选择器导入；多文件粘贴被拒绝并保留原选择。已识别的文件名前缀若与目标类型不符则拒绝；无法识别前缀时可手动指定对应栏位。
- **IN-02｜当前实现：**名称、版本不能为空；两者各最多 39 个 UTF-8 字节。控制字符和非法 Unicode 不接受，超长不截断。手动选入缺版本时可以先保留空值，但打包前须填写。
- **IN-03｜当前实现：**原始文件必须可读取且非空；PFC、LLC、M4、PLC 的预算分别为 250 KiB、250 KiB、512 KiB、2 MiB，超过预算显示告警但仍可生成；ESP32 上限为 2.5 MiB，超过则拒绝。联合包包含包头与填充总长最多 6 MiB。
- **IN-04｜用户已确认的目标，当前未达到：**先去掉 `.bin` 后缀，从首个 `_V`/`_v` 提取版本至下一个下划线或文件名末尾，保留版本中间的点与大小写。例如 `PFC_V1.2.3_test.bin` 提取 `V1.2.3`，兼容 `V000B01D15`。单独的 `V`/`v` 不算有效版本：一键加载跳过，手动导入须补全版本后才可生成。手动填写允许不以 V 开头，例如 `2026.11`，并遵守非空、不能仅为 V/v、无控制字符、有效 Unicode 和 39 个 UTF-8 字节上限。V0.0.4 在第一个点终止，且接受单独的 `V`，属于待处理差异。
- **IN-05｜当前实现：**一键加载仅扫描所选文件夹当前层，不扫描子目录。按五种类型前缀识别，大小写不敏感；PLC 候选不限后缀，其他类型须为 `.bin`。PLC 可从 `maya` 标识提取完整版本，例如 `PLC_maya-2.6.7.10.simage` 的名称为 `PLC_maya-2.6.7.10`、版本为 `maya-2.6.7.10`；匹配忽略大小写并保留原文，从 `maya` 至下一个下划线或名称末尾。若 `maya` 版本末尾是纯数字段（如无独立后缀的 `PLC_maya-2.6.7.10`），该段视为版本；实际纯数字后缀与版本无法仅凭文件名区分，可手动修正名称和版本。每类须恰有一个候选、可识别版本并通过输入检查，才更新该栏。
- **IN-06｜当前实现：**无候选、多个候选、缺版本或候选无效时保留该栏原选择；其他有效类型仍可独立更新。每类处理结果可见；不自动猜测最新版本。
- **IN-07｜当前实现：**一键清理重置五类文件、名称和版本，不删除磁盘文件，也不清除 FTP 配置、输出位置或既有操作记录。

### 3. 生成、偏移与包头

- **PKG-01｜当前实现：**选择 1～5 类固件，按 PFC、LLC、M4、PLC、ESP32 顺序生成；未选择类型没有有效目录项和固件数据。相同类型不能重复。
- **PKG-02｜当前实现，设备端待联调：**包头固定 4096 字节，首个固件从文件偏移 `0x1000` 开始；后续固件从前一个结束后向上 4 KiB 对齐的位置开始，尾部也对齐；固件间与包尾填充 `0xFF`。偏移基于联合 BIN 起始位置，不是芯片 Flash 地址或设备暂存分区地址。
- **PKG-03｜当前实现，设备端待联调：**记录每份原始固件的大小和 MD5，以及整包 MD5；整包计算时其包头 MD5 字段视为全零。MD5 用于一致性检查，不证明发布者身份。字段、字节序及预留区以 V1 格式说明为准。
- **PKG-04｜用户已确认的目标，当前实现需补强：**生成前检查输入与输出；已有输出须确认替换，输出不得与输入指向同一文件。对程序可处理的生成或校验错误，应保留或恢复覆盖前的旧包；若无法准备保护措施或输出位置不支持安全替换，拒绝覆盖并提示。若尝试恢复也失败，应保留仍可用的备份，并明确显示恢复失败和备份位置供人工处理；不承诺能修复硬盘损坏或断电造成的不可恢复丢失。当前过程先校验和写入同目录临时文件，再替换目标并复验；静态分析显示，替换后的复验或后续读取失败时，现有流程不能保证旧包仍在。该失败路径尚未实际复现。
- **PKG-05｜用户已确认、当前实现：**成功生成后，FTP 和设备升级页都自动改为新生成的联合包，即使之前手动选过其他文件。
- **PKG-06｜当前实现：**“查看包头”查看本次生成文件的前 4096 字节，按十六进制和 ASCII 显示并支持在包头范围内定位。文件不存在、不足 4096 字节或头部与生成时不同则提示错误；不提供独立整包校验按钮。升级页选择已有 BIN 时会另行尝试 V1 校验，这与独立校验入口是不同操作。
- **PKG-07｜用户已确认的目标，当前未达到：**生成前显示预计联合包总大小，包括包头和对齐填充；选择变更、预览刷新或生成前校验时按最新可读取文件大小重新计算。信息不足或无效、无法计算时明确显示待校验，不得将旧结果当成新结果。V0.0.4 预览显示各固件大小与偏移，整包大小仅在生成成功后显示。

### 4. FTP 上传及目录查看

- **FTP-01｜用户已确认的目标，当前未达到：**首次使用时自动填入此前指定的 FTP 地址和默认账号密码。指定目录为 `ftp://113.200.149.194/Update/`；真实凭据不记入本文。用户接受为满足首次单 EXE 使用而随 EXE 提供默认密码可能被提取；具体构建、注入及交付办法待设计。V0.0.4 启动时三个字段均为空，属于待处理差异。
- **FTP-02｜当前实现：**支持普通 `ftp://` 地址；可从包含账号信息的 URL 分离用户名和密码，密码输入遮罩。地址中的凭据特殊字符须按 URL 规则编码；用户名不能为空，密码可为空，凭据不能含换行或空字符；地址须有有效主机及端口，不接受查询参数或片段。普通 FTP 明文传输，不等同于 FTPS/SFTP。
- **FTP-03｜用户已确认、当前实现：**生成后自动关联为联合包来源，上传前校验 V1 包和容量限制。手动选择或拖入的本地文件归为普通文件来源，按原样上传，包括非 BIN 或空文件；不进行联合包校验，也不套用联合包 6 MiB 限制。上传确认框须明确告知该来源未校验。
- **FTP-04｜用户已确认、当前实现：**上传前展示文件和目标，并提醒同名文件可能被覆盖，由用户确认；不要求先自动查询服务器是否存在同名文件。目标路径由所选 FTP 目录和本地文件名组成。
- **FTP-05｜当前实现：**以二进制、被动 FTP 传输，连接和读写超时设置为 60 秒；只有服务器最终应答 226 或 250 才报告成功。失败显示失败结果；失败后服务器可能留有不完整文件。成功不包含远端文件回读校验，也不代表设备升级成功。
- **FTP-06｜当前实现：**“打开 FTP 目录”只读显示服务器条目，可提示当前选中文件是否存在同名条目；比较条目末段名称并区分大小写，不验证文件类型或内容。目录读取支持 UTF-8 和 GBK，列表上限为 10,000 条或 4 MiB，超限时提示不能完整读取。
- **FTP-07｜用户已确认的目标，当前未达到：**用户更改 FTP 地址、用户名或密码后，重开程序恢复上次输入；没有上次输入时采用指定的默认值。修改后的密码应使用 Windows 当前用户的保护机制加密保存在本机，而非以明文保存。V0.0.4 当前不保存这些字段。
- **FTP-08｜用户已确认的目标，当前未达到：**保存的 FTP 配置无法读取时提示用户，并恢复指定的默认地址和凭据；用户仍须在上传前核对并确认目标。配置存储、恢复时序和错误反馈的具体实现待设计。
- **FTP-09｜当前实现：**目录读取或上传进行时，FTP 相关操作及生成按钮暂不可用；上传过程中关闭程序需确认，并提示可能中断传输及留下不完整文件。
- **FTP-10｜用户已确认的目标，当前实现部分覆盖：**更换 FTP 服务器或端口时，若新地址没有携带账号密码，则清空之前的账号密码；同一服务器只改变目录时保留。若新地址携带账号密码，则使用地址中解析出的值。首次启动恢复默认或上次配置后，即使尚未上传或查看目录，首次更换服务器也须执行同样规则。V0.0.4 在已识别原地址后实现清除；新增加的启动恢复场景须单独实现和验证。
- **FTP-11｜用户已确认的目标，当前未达到：**配置或密码加密保存失败时提示本次仍可使用、下次可能无法恢复；不因此阻止本次上传。
- **FTP-12｜当前实现：**FTP 服务器确认上传完成后，依据本次实际使用的账号、密码、服务器、目录和文件名生成设备下载地址，并在操作结果上方提供只读地址及“复制”按钮，供操作人员填入 OCPP 平台。地址包含明文密码，只显示和按用户操作复制，不写入操作结果日志；开始下一次上传时清除旧地址。上传失败不提供本次地址。
- **FTP-13｜当前实现及设备限制：**生成的设备地址以现有 ESP-SECC OCPP 1.6 下载入口为约束：总长最多 122 字节，用户名和密码各最多 47 字节，文件名最多 80 字节；设备 FTP 解析不解码 `%XX`，且当前地址生成不支持 IPv6。目录、文件名或凭据需要转义或超限时，仍保留原上传结果，但提示无法生成设备地址，不提供可能指向错误文件或账号的链接。生成地址与 FTP 服务器返回成功均不证明设备可访问服务器或下载成功。

### 5. 操作结果

- **LOG-01｜用户已确认的目标：**添加／一键加载／清理固件、生成包、查看包头、上传和打开 FTP 目录，发生完成、失败或用户取消时，均追加一条带本机时间的结果；单纯切换页面、切换配色和编辑文字不记录。编辑引发的实时校验错误只显示在界面，不写入操作日志；实际点击加载或生成并失败时记录失败。记录按发生顺序追加，程序未关闭期间不因其他操作清除；关闭后可清除。错误用文字与红色表达。
- **LOG-02｜当前实现与差异：**操作结果区追加的条目格式为 `[yyyy-MM-dd HH:mm:ss]`；切换页面、清理输入和切换配色不清空，关闭重开后重新开始。V0.0.4 尚未覆盖上述所有取消路径，例如取消选择固件文件夹不会追加结果；名称或版本编辑触发的实时预览错误也可能写入日志，与目标不同。其余相关入口须逐项核对。
- **LOG-03｜当前实现：**结果区位于打包页面；切换到升级页时记录保持，但不是两页同时展示。导出、持久保存或集中日志不属于当前已确认功能。

### 6. 设备升级页面及边界

- **UPG-01｜用户已确认、当前实现：**顶部设备升级页分本地网口和远程运营平台两种配置；生成成功的新包自动关联，也可手动选其他本地 BIN。
- **UPG-02｜当前实现：**本地配置展示设备 IP、端口等字段；远程配置展示平台地址、CPID、账号和密码等字段。配置仅在当前窗口会话保留。
- **UPG-03｜当前实现：**本地模式下，选中且通过校验的联合包可以开始升级，正在执行或继续查询任务时按钮禁用。点击开始后重新读取并校验同一份包快照，查询设备状态并经人工确认后才发送；已插枪或状态未知时不发送。切换远程模式时开始按钮仍禁用，并提示运营平台接口未接入。
- **UPG-04｜当前实现与验证边界：**本地 LUP1 客户端已接入，默认地址和端口可修改。本地设备任务状态与目标版本核对分别判断；已观察到任务结束但版本核对未完成时，超时保留已结束的事实。结束应答未确认但有任务 ID 时，允许在同一会话手动继续查询，标明原设备和原包，不重发；未知或接收中不视为设备校验通过。没有任务 ID 时无法查询本次任务。真实 ETH、Flash、PLC、重启及平台连接恢复仍待联调；远程平台 API 未接入。

- **UPG-05｜本地版本读取：**不需选升级包，可按当前设备 IP 和端口手动读取 PFC、LLC、M4、PLC、ESP32 的运行版本；复用现有 LUP1 版本查询。查询结果写入“升级日志”，不使用模态弹窗；分别标注已读取的版本、未就绪、不支持查询或不可用，查询失败不显示为有效结果。不发送固件或启动升级，且不与本地升级或继续等待并行。
- **UPG-06｜停止占位：**本地升级页将“开始升级”和禁用的“停止升级”相邻排列，并标明停止协议未接入。不发送停止命令、不关闭连接，也不取消设备任务。停止协议和设备端行为另行设计。
- **UPG-07｜进度与升级日志：**本地升级页在设备确认开始后显示 0%，每确认一个数据块就更新横向进度条和百分比，界面及进度日志不显示字节数。升级日志带时间，记录 TCP 连接、升级请求与受理、进度每跨一个十个百分点档位、设备接收校验、状态和逐目标版本对比。版本明细未变时不重复记录。100% 仅表示所有包字节已确认，不表示校验通过或设备安装成功。原“操作结果”保留，日志不跨应用重启。

## Testing Decisions｜验证方式

- **验收接缝已获用户认可：**以 Windows 实际界面操作作为主要功能入口；用独立解析程序核验包格式；FTP 先用本机模拟服务器，真实 FTP 和设备／平台分别联测。优先复用现有测试接口，不为规格整理新增生产接口。
- 测试验证用户可观察的输入、结果、边界和文件内容，避免只测试内部函数调用或照抄实现。
- 文件输入：覆盖四类预算及预算加一、ESP32 上限及上限加一、6 MiB 整包边界、空文件、不存在、类型不匹配、名称／版本 UTF-8 边界、手动和一键加载的区别、重复候选、子目录和保留原选择。
- 版本：覆盖 `V1.2`、`V1.2.3`、`V000B01D15`、大小写、后续下划线、单独的 V/v 和手动输入 `2026.11`；已确认的新规则在实现前应标未通过或未运行，不把当前截断行为当作通过。
- 打包和包头：覆盖所有非空类型组合、固定顺序、4 KiB 对齐、包内偏移、原始固件数据、头部字段、单项和整包 MD5、错误填充、重叠、截断及非法元数据；检查生成前总大小预计及选择变化、输出覆盖确认、输入保护、生成及后续校验失败时的旧包保护、不支持安全替换的拒绝、恢复失败时的可用备份和位置提示、查看范围和生成后的自动关联。
- FTP：模拟服务器覆盖账号解析、服务器变更时的凭据处理、普通文件与联合包来源、上传确认、成功状态码、认证／写入／传输失败及目录列表；覆盖首次默认、上次配置恢复、密码本机加密、配置不可读取时的提示与回退、保存失败时可继续使用；特别验证启动恢复后首次更换服务器、同服务器只改目录及新地址携带凭据三种场景。真实服务器上的网络、权限和实际远端文件需另行验证。
- 结果与界面：验证指定操作完成、失败和取消均有时间戳，切换页面、切换配色与编辑文字以及编辑触发的实时校验提示不单独记结果，执行操作失败仍记录；验证重复记录、错误文字和颜色、页面／清理／配色切换保留、关闭重开重置；七种颜色、首次银色、恢复选择和图标不变按各自规范验证。
- 升级页：验证本地／远程表单切换、生成包与手动选择、按钮启用条件和远程占位。用本机模拟服务区分任务结束与版本核对、验证结束应答丢失后的只读查询及原任务地址展示；真实设备另立验收。
- 现有项目已有包核心测试、独立格式核验、FTP 模拟测试、UI 契约及外观测试作为先例。历史测试记录只对其执行版本和环境负责；本稿撰写时未重跑测试，也未连接真实设备或 FTP。
