## 实测结果

Windows 上执行 `tests/run-tests.ps1`，最终输出保存在 `evidence/windows-tests.log`：

- 31 种非空固件组合全部通过；逐项核对类型顺序、预览偏移、4 KiB 对齐、`0xFF` 填充、原文件提取及哈希。
- 预算上限样例包含五类固件，大小 **5,628 KiB / `0x57F000`**；五个偏移与讨论稿示例一致。
- 包头、固件和填充被修改、总长度不符、被截断、类型重复、偏移越界和非法 UTF-8 等情况均被拒绝。部分破坏用例先重算整包 MD5，以独立覆盖固件 MD5 与结构/填充检查。
- 未选择固件、空文件、版本为空、输入不可读、超长 UTF-8 字段、ESP32 超限、总包超限及输出目录不存在均被拒绝；PFC、LLC、M4、PLC 四类分别超建议预算时有警告且允许打包，界面也实测了 PFC 超预算提醒。
- 测试了输出等于输入、输出与输入是同一硬链接、已有输出被占用和失败时保护旧文件；还测试已有输出正常替换。
- 测试路径、文件名和固件名称含中文及空格；版本包含 `V000B01D15`。
- 核心测试记录 **260,531 次断言**，其中大量断言逐字节检查填充，并非 260,531 个独立用例。
- 在 Windows 实际窗口中测试了预览、生成和校验展示；另外自动操作**交付 EXE 本身**的文件选择和保存对话框、默认名称、版本输入、生成、打开并校验，以及缺版本和损坏包的错误提示。窗口截图为 `evidence/gui-smoke.png`。

首次新增界面错误提示测试时，测试程序未能用控件 ID 关闭系统提示框；修正自动化关闭方式后重跑通过。`evidence/windows-tests-initial-automation-failure.log` 保留首次运行的标准输出；失败细节为 `ReleaseUiTests.DismissError: Could not click a control`。这次失败不记为通过。

独立 Python 读取器未调用 C# 打包/校验实现。它重新解析并核对 31 种组合、预算上限包、提取数据、整包 MD5、各固件 MD5 和填充；结果见 `evidence/independent-verifier.log`。42 个 Windows 测试输入和输出打包保存在 `evidence/windows-fixtures.zip`，解压后可作为 `tests/independent_verify.py` 的输入目录。

交付样包的原始文件、包和预期值也由独立脚本核验，结果见 `evidence/vector-verifier.log`。样包是合成数据，不能用于设备升级。

## 未验证及后续接口

- 未在 Windows 11 或其他 Windows 10 版本上实跑；当前实测仅覆盖上述 Win10 环境，其他桌面缩放比例、语言环境和极端长路径也未全面覆盖。
- 未接入或测试 ESP32 设备、真实固件烧录、TCP、FTP、OCPP、M4/PFC/LLC/PLC Bootloader、设备掉电恢复或 NVS 状态。
- V1 的字节布局、扩展规则、接收端错误处理及升级阶段协议仍需相关属主评审并对接；6 MiB 暂存区、2.5 MiB 应用槽和设备分区迁移仍需后续设计与验证。
- MD5 只验证一致性，未实现签名或发布者身份验证。
