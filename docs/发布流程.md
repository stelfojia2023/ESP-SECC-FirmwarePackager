# 发布流程

面向操作者和编码代理。发布、合并和推送需用户明确授权；本文只描述授权后如何执行，不改变授权规则。

## 1. 前置检查

- 确认目标版本源码已在 `main`，且 `dist/FirmwarePackager.exe` 仍是上一正式版（未发布时不要提交新 EXE）。
- 确认 Windows 交互桌面已解锁、没有全屏应用或剪贴板工具占用；`run-tests.ps1` 会先运行剪贴板预检。
- 不把真实 FTP 凭据、设备信息或完整下载地址写入文档、日志或提交。

## 2. 构建唯一发布 EXE

从目标 `main` 提交复制源码到 Windows 本地目录后构建一次：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

记录 `dist\FirmwarePackager.exe` 的 SHA-256。**从此刻起不再重建**；后续验证、`dist` 提交和 Release 资产必须是这同一份文件。每次 `csc` 构建的二进制摘要不同，重建会使记录失效。

## 3. 验证

在已解锁的 Windows 桌面执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run-tests.ps1
```

- 全量约 4–6 分钟；每个用例结束输出 `DONE <case> (<秒>s)`。
- 失败时只重跑相关用例，避免整轮等待：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run-tests.ps1 -Only gui
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run-tests.ps1 -Only release-ui,release-ftp
```

- 开头输出 `PREFLIGHT clipboard ...`。出现 `PREFLIGHT WARN` 表示系统剪贴板争用，先关闭剪贴板工具/同步软件并重试；不要把它当作产品缺陷，也不要在未重试的情况下宣称通过。
- 全量通过后执行：

```powershell
python tests/independent_verify.py "<证据目录>\core results"
python tests/verify_vector.py test-vectors
python tests/check_docs.py
python tests/check_version.py
python tests/check_release_ready.py
python tests/test_check_release_ready.py
```

自动组仍需运行 `tests/run-selected.ps1 -Groups all`。真实设备、运营平台和真实 FTP 不在本流程的自动验证范围内。

从 WSL 调用时使用 `tests/run-tests-from-wsl.sh`，它会先同步到 Windows 临时目录并把日志写在 Windows 侧，避免标准输出中继和手工复制导致的旧文件问题：

```bash
bash tests/run-tests-from-wsl.sh
bash tests/run-tests-from-wsl.sh gui,release-ui
```

## 4. 更新发布元数据

同一版本内的准备和修正提交可共用目标版本。发布提交包含：

- `.github/release.json`：`tag`、`title`、`exe_sha256`（第 2 步记录的摘要）。
- `README.md`：源码版本改为 `VX.Y.Z（发布构建）`，下载链接指向新 tag。
- `docs/releases/vX.Y.Z.md`：本版更新、验证范围与边界。
- `dist/FirmwarePackager.exe`：第 2 步的同一份文件。

提交前运行：

```powershell
python tests/check_release_ready.py
python tests/check_docs.py
python tests/check_version.py
```

`check_release_ready.py` 校验版本、tag、README 下载链接、发布说明和 EXE 摘要一致；开发构建也用它（此时源码版本应比最近 Release 新）。

## 5. 提交与推送

发布提交信息必须**严格等于** `Release vX.Y.Z`。`publish_release.py` 按整条提交信息校验，不能附加正文或署名行。

```bash
git add .github/release.json README.md dist/FirmwarePackager.exe docs/releases/vX.Y.Z.md
git commit -m "Release vX.Y.Z"
git push origin main
```

## 6. 核对结果

推送后工作流约 1–2 分钟完成：

```bash
gh run list -L 3
gh release view vX.Y.Z --json tagName,isDraft,isPrerelease,assets
```

必须核对：

- tag 指向发布提交；
- Release 不是 draft/prerelease；
- `FirmwarePackager.exe` 的 `sha256:` 资产摘要与 `release.json`、`dist` 文件一致；
- `SHA256SUMS.txt` 存在。

三者不一致时停止，不要覆盖已有 Release 资产。

## 7. 已知环境问题

桌面用例会移动鼠标并使用剪贴板。以下现象属于环境争用，不是产品缺陷：

- `CLIPBRD_E_CANT_OPEN`：剪贴板被其他进程短暂占用；测试会自动重试，持续出现时关闭剪贴板工具后重跑。
- 焦点锁或窗口遮挡：测试会等待并重试；仍失败时确认目标窗口未被其他应用覆盖。
- 确认框文本为空：测试等待文本就绪后再断言。

不要在发布阶段修改产品行为来迁就环境；稳定性修复应作为普通 PR 在发布前完成并升版。
