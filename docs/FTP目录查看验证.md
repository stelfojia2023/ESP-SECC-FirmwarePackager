# FTP 目录查看与默认地址验证

- 基线：GitHub `main` 的 `34fbb6deee4362ac8863bcb868704f2d581d0185`。
- 交付程序：`dist/FirmwarePackager.exe`，SHA-256：`29879529d436293d5d184a6c2107e51cc1f75a0f1de109b81f925f10370ba2c6`。
- 在 Windows 10 10.0.19045 构建，使用系统 .NET Framework 编译器；无需附带图标或声音文件。

## 行为与边界

- “打开 FTP 目录”位于“上传到 FTP”左侧，两个按钮与其他主要按钮等尺寸。读取当前地址的服务器目录，不要求先选本地文件，也不会上传、删除或更改服务器文件。
- 已选文件时，只按区分大小写的名称比较并提示是否存在同名条目；同名条目也可能是目录，不能证明远端内容一致。空列表和读取失败分别提示；超过 10,000 条或 4 MiB 时不把部分列表当作完整结果。
- 读取目录使用 FTP 的 NLST 命令，按 UTF-8 解码；不能按 UTF-8 解码时尝试 GBK。服务器的目录权限、编码和 NLST 行为可能不同。
- 地址、用户名和密码为指定的启动默认值，可以修改；密码遮罩，修改值不会持久保存。默认密码内置在 EXE 和源码中。切换服务器时不会自动携带旧账号密码。

## 本轮验证

- `tests/run-tests.ps1`：文件名、包头、31 种固件组合、包格式边界、FTP 上传、目录读取、WinForms 界面和交付 EXE 实际拖放/打包均通过。
- 本机模拟 FTP：目录项、中文及空格、UTF-8/GBK、空目录、530 认证失败、550 目录权限拒绝、451 传输失败、数量和字节上限；验证读取不发送上传命令。
- 将 EXE 单独复制到空目录，直接启动该程序，通过实际 Windows 控件验证默认值、密码遮罩、按钮尺寸与位置、目录内容和认证失败提示。
- UI 合同测试覆盖默认值、紧凑窗口、按钮间距、忙碌时控件禁用；125% 字号下的按钮文本尺寸单独检查。独立 Python 校验器和交付样本校验通过。
- 图标源文件与基线一致，EXE 内图标的七种尺寸像素比较通过。`viewer.png` 是使用合成数据的 WinForms `DrawToBitmap` 渲染，不是桌面截图。
- 早期进程内自动化对认证失败弹窗的关闭发生时序失败，记录于 `initial-ui-automation.log`。重复的进程内弹窗检查已移除，最终通过独立 EXE 的真实窗口测试覆盖该失败路径。

本轮 FTP 测试仅连接本机模拟服务器，未连接实际服务器，因此不声称实际服务器的目录权限、编码或连接情况已验证。详细输出及本轮校验和见 `evidence/ftp-directory/`。
