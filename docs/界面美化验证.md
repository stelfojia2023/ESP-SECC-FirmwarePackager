## 通过的测试

- `tests/run-tests.ps1`：核心 31 种非空固件组合、5,628 KiB 预算边界、格式和异常路径通过，核心测试累计 260,531 次断言；其中大量断言逐字节检查填充，并非 260,531 个独立测试用例。
- 在真实 Windows 窗口中检查五行预览、生成和校验、预算提示、路径输入、小窗口滚动、机器人图标；逐个测量“浏览”“清除”和输出、上传按钮的文本边距，覆盖默认与最小窗口尺寸，并以放大 25% 的字体度量重复检查。长路径、名称和版本可通过悬停查看完整内容。
- 测试了真正跨进程的 Windows 文件拖拽，以及在仅有 EXE 的目录运行交付程序、浏览、保存、生成、打开旧 V1 样包、损坏包错误提示。界面测试截图为 `evidence/ui-refresh/gui-five.png`；完整输出分别见 `windows-tests.log` 和 `standalone-tests.log`。
- FTP 测试使用本机回环测试服务器与合成账号：解析含账号密码的地址、默认端口、百分号编码、中文及空格目录、密码遮罩；覆盖 226/250 成功及接收字节一致、530 认证失败、550 拒绝写入、传输后 451 失败、无效包拒绝。界面测试触发上传按钮和确认框，并检查成功、失败提示及切换服务器时清除旧凭据。没有连接用户示例中的服务器。
- Python 独立读取器重新核验 31 种组合、预算样包和已有 V1 样包，结果分别见 `independent-verifier.log` 和 `vector-verifier.log`。
- `test-vectors/five-test-bins.zip` 包含五个不同类型的合成测试 BIN；归档中的 SHA-256 与本机测试文件逐个一致，不能用于真实设备升级。

证据日志为便于跨平台检索统一使用 LF 行尾并去除行尾空格和末尾空行，不改变有效测试内容。

界面测试中的一次早期原生拖拽自动化因未触发源窗口鼠标事件而超时，记录保留为 `initial-drag-automation-failure.log`；调整测试的焦点与重试处理后，最终交付 EXE 和单文件副本均完成真实拖拽测试。该早期失败不计为通过。
