# 设备升级页面与 FTP 默认目录验证

- 基线：GitHub `main` 的 `ab4facdb359f7b89dec76cf6f67a6f39bab2f63c`。
- 本版 `dist/FirmwarePackager.exe` 的 SHA-256：`28c3bf2974acce6b1086b50d5825c761645b9c0facd104b29c6206ea363005c3`。
- FTP 默认目录按用户新指定的路径更新，原默认账号与密码保持不变。

## 已实现

- 顶部“固件打包”和“设备升级”页签；升级页支持本地网口、远程运营平台两种配置，包含设备 IP／端口或平台地址／CPID／账号／密码。切换页面及方式时，本次窗口的输入保留，远程密码遮罩。
- 成功生成联合包后，将该本地文件路径和包内固件版本自动带入升级页，无需重新选择或复制。也可拖入、粘贴路径或选择其他 BIN；下次成功生成新包时重新关联最新生成的文件。
- 选择的文件若无法作为本工具联合包识别或校验，会显示提示；当前仍可选入该 BIN，不表示设备支持其格式。升级页按内容使用较紧凑的窗口，切回打包页恢复此前大小。
- 本地协议和运营平台接口尚未确定或接入。“开始升级”禁用；页面不会连接设备、发送升级请求或声称升级成功。

## 本轮验证

- Windows 10 10.0.19045 原生构建；核心包格式、FTP 模拟服务器、界面操作、拖放、包头和独立 EXE 回归通过。
- 实际交付 EXE 测试覆盖打包后自动带入升级页、切换本地／远程、CPID 保留、通过系统文件选择窗口更换 BIN，以及未接入状态。
