# 测试用例与执行入口

本文件是当前测试清单，不是每次运行的结果记录。**自动**表示仓库中已有可执行测试；**桌面**表示需在已解锁的 Windows 桌面运行；**待实现**表示规格已确认但当前版本尚不满足。每次 PR 应记录实际运行的命令、结果和未运行项。

历史版本的 `evidence/` 清单记录当时的文件摘要；核对时应使用对应版本的源码，后续修改的文件不应与旧摘要比较。

## 日常选测

先用 `python .github/scripts/select_tests.py --base <基线提交>` 查看建议；命令包含本地未提交和未跟踪文件。也可根据下表补充组别，范围不确定时使用 `all`。Windows 执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\run-selected.ps1 -Groups "core,ftp"
```

| 组 | 覆盖 |
| --- | --- |
| `filename` | 文件名类型及版本识别 |
| `core` | 联合包组合、边界、异常和独立格式核验 |
| `ftp` | 模拟 FTP 上传和目录 |
| `header` | 包头查看 |
| `ui` | UI 契约、输入、一键加载、升级页和日志 |
| `appearance` | 七色、对比度和设置 |
| `typography` | 字体及 DPI 声明诊断 |
| `vector` | 固定样包独立核验 |
| `publisher` | 发布脚本的模拟测试 |
| `local-upgrade` | LUP1 协议边界和短读写；不连接真实设备 |
| `desktop` | 默认只编译桌面测试；在已解锁的 Windows 上添加 `-RunDesktop` 才执行真实鼠标和窗口测试 |
| `all` | 以上全部自动组；仍需另跑桌面完整回归 |

涉及窗口交互时，选 `desktop` 并加 `-RunDesktop`；需要比对图标时再加 `-BaselineExe "<基线 EXE>"`。GitHub CI 不传这些参数，因此桌面交互和图标比对未由 CI 实际运行，需在 PR 中写明本地结果或未运行原因。

文档和选测规则自检使用 `python tests/check_docs.py`、`python tests/test_check_docs.py`、`python tests/test_select_tests.py`。链接检查只验证仓库内相对目标，不检查外网、页面锚点或参考式链接。

每个 PR 须按项目入口升版；`python tests/check_version.py --base <完整基线提交 SHA>` 验证相对基线加 1，以及窗口、程序集、manifest、README 和测试断言的一致性；`python tests/test_check_version.py` 验证检查器。因升版涉及界面与 manifest，纯文档 PR 也需运行相关界面自动组；其他功能按影响选测。

GitHub 选测输出见 Actions 的作业日志；涉及构建时上传 EXE、摘要和测试生成的证据作为工作流产物。

## 发布前完整验证

先运行 `run-selected.ps1 -Groups all`，再在已解锁的 Windows 交互桌面运行 `tests/run-tests.ps1`；后者会打开窗口并移动鼠标。硬链接保护测试需要支持硬链接的卷。对其输出目录中的 `core results` 执行 `python tests/independent_verify.py "<证据目录>\core results"`，并执行 `python tests/verify_vector.py test-vectors`。图标比对使用 `IconPreservationTests.cs` 对照基线与候选 EXE。

真实桌面回归由操作者执行并留证；GitHub CI 的发布流程不自动核验该本机证据。真实 FTP、运营平台、设备升级和不同系统缩放需要各自的环境与证据；模拟服务、字体放大或自动检查不能替代它们。
