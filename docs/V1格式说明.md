# 联合固件包 V1 格式说明（待评审）

本格式是独立打包工具提出的候选格式，不是已冻结的设备通信协议。现有 ESP-SECC 固件没有接入本格式的联合包解析及多模块升级逻辑；不能据此声称生成的 BIN 可供现有设备直接升级。

## 基本约定

- 数据按字节存储，所有多字节整数均为**无符号小端序**。
- 固定包头 `4096` 字节，其后仅保存被选中的 1～5 个固件。类型顺序固定为 PFC、LLC、M4、PLC、ESP32。
- 每份固件的起始位置和整个包的末尾都向上对齐到 4096 字节。固件间和包尾的对齐填充为 `0xFF`。固件大小与固件 MD5 只覆盖原始固件字节，不包括填充。
- 包内偏移均从联合 BIN 的第 0 字节开始计数，**不是**目标芯片的 Flash 烧录地址。格式不包含暂存分区地址。
- 字符串使用严格 UTF-8、显式字节长度，不带终止符。长度上限按编码后的字节数计算，不能静默截断；空白字符串、控制字符和非法 Unicode/UTF-8 均被拒绝。未用的字符串空间置 `0x00`。
- V1 不填入未经提供的机型、硬件版本、目标烧录地址等信息。预留字节均为 `0x00`，V1 读取器要求它们保持为零；未来使用这些区域须定义新的格式版本并协调解析器，V1 不能自行解释扩展。

## 包头布局

包头固定为 `0x0000～0x0FFF`。表中偏移均相对联合 BIN 开头。

| 偏移 | 字节数 | 字段 | V1 取值及说明 |
| --- | ---: | --- | --- |
| `0x0000` | 8 | 包标识 | ASCII `SECCPKG1`，8 字节，无终止符 |
| `0x0008` | 2 | 格式版本 | `1` |
| `0x000A` | 2 | 包头长度 | `4096`（`0x1000`） |
| `0x000C` | 4 | 联合包总长度 | 包头、固件和全部填充之和，实际文件长度必须相等 |
| `0x0010` | 2 | 固件数量 | `1～5` |
| `0x0012` | 2 | 目录项长度 | `256`（`0x100`） |
| `0x0014` | 4 | 目录偏移 | 固定为 `128`（`0x80`） |
| `0x0018` | 16 | 整包 MD5 | 二进制 16 字节，计算方式见下文 |
| `0x0028` | 88 | 预留 | 全 `0x00`，至 `0x007F` |
| `0x0080` | 至多 1280 | 固件目录 | 按固件数量排列，每项 256 字节；最多 5 项 |
| 目录结束处 | 至 `0x0FFF` | 未使用目录和预留区 | 全 `0x00`，不为未选固件保留有效目录项 |

包头目录最多到 `0x057F`；剩余 `0x0580～0x0FFF` 是预留区。当数量小于 5 时，未使用的目录项也必须为零。

## 256 字节固件目录项

下表偏移相对当前目录项起点；第 `i` 项（从 0 开始）的起点是 `0x80 + i × 0x100`。

| 项内偏移 | 字节数 | 字段 | 说明 |
| --- | ---: | --- | --- |
| `0x00` | 2 | 类型 | `1=PFC`、`2=LLC`、`3=M4`、`4=PLC`、`5=ESP32` |
| `0x02` | 2 | 预留 | 全 `0x00` |
| `0x04` | 4 | 包内偏移 | 固件数据首字节位置，4096 字节对齐 |
| `0x08` | 4 | 原始大小 | 原始固件字节数，必须大于零 |
| `0x0C` | 16 | 固件 MD5 | 原始固件字节的 MD5，二进制 16 字节 |
| `0x1C` | 2 | 名称长度 | UTF-8 字节数，`1～96` |
| `0x1E` | 2 | 版本长度 | UTF-8 字节数，`1～64`；支持 `V000B01D15` 等文本 |
| `0x20` | 96 | 名称 | 按名称长度读取，其余字节为 `0x00` |
| `0x80` | 64 | 版本 | 按版本长度读取，其余字节为 `0x00` |
| `0xC0` | 64 | 扩展预留 | 全 `0x00` |

目录必须按类型编码递增，不允许重复类型。第一个固件的偏移为 `0x1000`；后续固件紧接前一固件按 4 KiB 向上对齐的位置；最后一个固件之后也填充到 4 KiB。读取器拒绝额外空洞、重叠、越界、错误填充值和多余包尾。

## 整包 MD5

1. 将偏移 `0x0018～0x0027` 的 16 字节置为 `0x00`。
2. 对从 `0x0000` 到 `总长度 - 1` 的**整个**联合 BIN 计算 MD5，包括包头、全部固件和所有 `0xFF` 填充。
3. 把得到的 16 字节写入该字段。
4. 校验时读取字段，再把同一范围视为 `0x00`，以同样范围重新计算并比较。

这个值通常**不同于直接对最终 BIN 执行普通 `md5sum`**。格式不额外定义包头 CRC，因此不存在 CRC 与 MD5 的循环依赖。MD5 仅用于数据一致性检查，不能验证发布者身份或防止恶意篡改。

## 工具容量限制与设备边界

- 联合包总长度，包括包头和填充，不超过 **6 MiB**。
- PFC、LLC、M4、PLC、ESP32 原始固件分别不超过 **250 KiB、250 KiB、512 KiB、2 MiB、2.5 MiB**。空文件和单项超限会被拒绝；联合包校验也使用这些上限。
- 上述上限是本工具的接收限制，6 MiB 暂存区与 2.5 MiB ESP32 应用槽仍是设备端候选方案，不能据此推断现有设备具备相应分区。

五固件分别达到工具上限时，原始固件合计 5,620 KiB，加包头和填充后为 **5,628 KiB（`0x57F000`）**；偏移依次为 `0x001000`、`0x040000`、`0x07F000`、`0x0FF000`、`0x2FF000`。

## 接收端后续对接

必须由 ESP32 接收端评审并共同冻结标识、版本、字段、字符串、范围和错误处理；另需设计联合包下载与暂存、解析和校验、升级对象编排、各目标协议、掉电恢复及分区迁移。它们不属于本工具的已实现功能。
